# ADR 008: テクニカル指標セット（保存と呼び出し）

## ステータス

Accepted（v0.2.0 / Phase 5）

## コンテキスト

v0.2.0 Phase 3 で分類付きの指標カタログを載せ、チャート分析の指標指定は `enabledIds`（カタログ ID の集合）になった。
この状態は React のメモリ上だけであり、リロードするとおすすめ構成に戻る。
名前付きの構成を複数持ち、後から検索して呼び出す手段がなかった。

指標の**計算結果**は [ADR 004](004-technical-analysis.md) / [ADR 006](006-indicator-catalog.md) どおり DB に保存しない。
保存したいのは「どの指標を ON にするか」というトグル集合である。

## 決定

**ユーザー所有の名前付き `IndicatorSet` を PostgreSQL に保存し、チャート分析から保存・検索・呼び出しする。**

- 保存対象はカタログ ID 配列のみ。パラメータの自由編集は対象外（ADR 005/006 の延長）
- 同一ユーザー内でセット名は一意（`@@unique([userId, name])`）
- `elliott`（説明のみ）と未知 ID は保存できない。空配列は許可する
- 生出来高（`volume`）は描画フラグなのでセットに含めてよい。計算 API には送らない（既存どおり）
- 公開 API（JWT 必須）:
  - `GET /indicator-sets` — 自分の一覧（`createdAt` 昇順）
  - `POST /indicator-sets` — `{ name, indicatorIds }`
  - `DELETE /indicator-sets/:id` — 204。他人所有は NOT_FOUND
- 検索はクライアント側。セット名の部分一致と、チェックした指標をすべて含む AND
- UI:
  - 保存は現行の指標設定ウィンドウ内
  - 呼び出しは独立した新規ウィンドウ（モードレス / 別ウィンドウ）。指標設定と排他にしない
  - 呼び出すと現行の `enabledIds` を置き換え、開いている指標設定とチャートに反映する
- リネーム / 上書き PATCH は今フェーズの対象外。直し方は削除して再保存
- トレンドスコアの正本セットとは連動しない（[ADR 007](007-trend-score.md)）

## 理由

- ウォッチリスト / シグナル定義と同じ「ユーザー所有の名前付きコレクション」に揃えると、所有権・JWT・エラーコードの扱いが既存どおりになる
- カタログ ID だけを持てば、パラメータ既定値（ADR 006）と矛盾しない
- 呼び出しを独立ウィンドウにすると、現行の指標設定を見ながらセットを探せる
- 件数が少ない前提では専用検索 API よりクライアントフィルタの方が契約が単純

## 結果・制約

- 指標パラメータ・計算結果の永続化は対象外
- セットのリネーム / 上書き、端末ローカル（localStorage）保存は対象外
- 分足・月足・リアルタイムは対象外
